# Known-failing backend tests, as of t_2af95a6b (2026-10-01).
#
# WHY THIS FILE EXISTS
# --------------------
# The backend-test job in .github/workflows/ci.yml carried
# `continue-on-error: true`, so a failing pytest run could not fail the
# workflow. 19-21 tests were red for the entire life of the tree and every PR
# stayed green. Removing the flag outright would turn main permanently red on
# the first push, so instead the suite is gated against this baseline:
#
#   * a test that fails and is NOT listed here  ->  the job fails
#   * a test that is listed here                ->  reported, tolerated
#   * a listed test that now passes             ->  reported as a warning, so
#                                                  the entry gets deleted
#
# This is a ratchet, not an excuse. Entries may only be REMOVED, never added,
# and scripts/ci_backend_gate.py enforces that: adding an entry fails the job
# unless it also carries a reason. That is the opposite of the
# "pre-existing, ignore it" framing that hid this in the first place.
#
# Each entry below was verified to fail on `main` @ 036eca9d against a
# Postgres 16 database built by `alembic upgrade head`. The audit that
# classified them is docs/QA_T46761765_FAILURE_AUDIT.md (branch
# qa/t_46761765-failure-audit); its finding was 0 real production defects,
# 1 real test defect with a security consequence (already fixed on
# qa/t_46761765-failure-audit), and the rest defective tests.
#
# OWNER: t_9edcc69c repairs the defective test files, t_ee78caa8 the duplicate
# PaymentInitiateRequest. Entries should disappear as those land.
#

# ignored.
